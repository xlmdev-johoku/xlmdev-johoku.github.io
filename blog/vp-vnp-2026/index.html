Claude は Valiant 予想を証明したのか ―― VP ≠ VNP の主張をどこまで確かめられたかで読む

2026年11月23日、Anthropic が GitHub に1本の論文を置きました。題は「VP ≠ VNP over every field」で、著者の欄には「Claude」とだけ書かれています。計算の難しさを扱う分野で47年間解かれていなかった予想を、AI が証明したという主張です。その約3時間半後には、OpenAI も同じ結論の論文を公開しました。

報道では「P ≠ NP の代数版が解けた」と紹介されています。この記事では、まずこの予想がどんな問題なのかを説明します。そのうえで、主張されたこと・確かめられたこと・まだ確かめられていないことを整理します。

この記事のポイント

  • Anthropic と OpenAI がそれぞれ、AI の書いた論文と Lean の証明で「VP と VNP は異なる」と主張した。P ≠ NP が解けたわけではない。
  • Lean の検査は通っている。これは「書かれた主張がきちんと証明されている」ことの強い証拠になる。
  • ただし、書かれた主張が本当に Valiant の予想なのかを、人間の専門家はまだ確かめていない。両社とも「人間は証明を確かめていない」と自ら書いている。

この記事は2026年11月26日時点の情報です。

Valiant 予想とはどんな問題か

まず、計算の手間をどう測るかから説明します。

足し算と掛け算だけの回路で多項式を計算する

この予想で使う計算の模型は算術回路です。算術回路は変数と定数から始めて、足し算と掛け算を繰り返して1つの多項式を作ります。1回の足し算や掛け算を1つのゲートと数え、ゲートの数を計算の手間とみなします。

たとえば \((x+y)^{2}\) は \(x+y\) を1回計算し、それを自分自身と掛ければ作れます。展開した \(x^{2}+2xy+y^{2}\) をそのまま計算するより、ゲートが少なくて済みます。どんなにうまく組んでも何個のゲートが要るか。それがこの分野の問いです。

行列式と permanent は符号しか違わない

ここで、よく似た2つの多項式を比べます。正方行列の行列式と permanent です。permanent は行列式の式から、項につく符号（プラスとマイナス）を取り去ったものです。

n×n の行列では、どちらも項が n! 個あります。n が30なら約 \(2.65 \times 10^{32}\) 個で、すべての項を並べて足すことはできません。

行列式には、この項を並べずに済む速い計算法があります。ある行に別の行の定数倍を足しても行列式の値は変わらないので、ガウスの消去法のように行列を簡単な形に変えてから計算できます。手間は n の多項式で収まります。

permanent には、こうした便利な性質が知られていません。知られている最速の方法でも、手間は n について指数的に増えます。1979年、計算機科学者の Leslie Valiant は「permanent は多項式サイズの算術回路では計算できないだろう」と予想しました。これが Valiant 予想です。

VP と VNP

Valiant 予想は2つのクラス（多項式の集まり）の言葉で書かれます。

  • VP：変数の数と次数に対して、多項式サイズの算術回路で計算できる多項式の族。行列式はここに入ります。
  • VNP：VP の多項式を、補助の変数に 0 と 1 を入れたすべての場合について足し合わせて得られる族。足し合わせる場合の数は指数個になりえます。permanent はここに入り、しかも VNP の中でいちばん難しい多項式の1つです（VNP 完全）。

VP は VNP に含まれます。そのうえで「VP と VNP は等しくない」というのが Valiant 予想です。permanent が VNP 完全なので、これは「permanent は多項式サイズの回路で計算できない」と言っても同じです。

コラム：「少なくともこれだけ要る」を示す難しさ

速い計算法を1つ見つければ「これだけあれば計算できる」（上界）は示せます。反対に「どんな回路でも少なくともこれだけ要る」（下界）を示すには、ありとあらゆる回路を相手にしなければなりません。そのため下界はとても難しく、形に制限のない算術回路では、これまで「変数の数×対数」程度の下界しか知られていませんでした。今回の論文によると、m×m の permanent（変数は \(m^{2}\) 個）について知られていた最良の下界も \(m^{2}\log m\) 程度でした。

11月23日に何が公開されたのか

公開の経緯を、確かめられた事実だけで並べます。時刻は協定世界時（UTC）です。

Anthropic の論文が主張していること

論文の主定理は、permanent を計算する算術回路のゲート数に下界を与えます。ある正の定数 \(c\) があり、\(m\) が十分大きければ、m×m の permanent を計算するどの回路も次の数より多くのゲートを要します。

\[ m^{\,c\,(\log_{2} m)^{1/3}} \;=\; 2^{\,c\,(\log_{2} m)^{4/3}} \]

\(m\) のどんな多項式よりも速く増える（超多項式）。そのため permanent は VP に入らず、VP ≠ VNP が従う。ただし指数関数よりはずっと遅く増える（準多項式）。

論文はこの下界を、実数だけでなくすべての体（足し算・引き算・掛け算・割り算ができる数の体系）について示したと主張しています。標数2の体では permanent が行列式と一致してしまうので、そこでは permanent の代わりに Hamiltonian cycle 多項式という別の VNP 完全な多項式を使います。近似的に計算する回路にも同じ下界が成り立つ、とも主張しています。

論文自身、既知の上界（指数的）との差はまだ大きいと書いています。「permanent の計算にちょうど何個のゲートが要るか」がわかったわけではありません。

翌日の更新で、OpenAI はさらに9本の論文を追加しました。更新履歴には、そのうち「階層」と「回路の下界」を扱う2本が11月23日の論文の結果を含む、とあります。2本のうち1本は VP より小さいクラスまで含めた Valiant のクラスの階層全体が真に分かれると主張しています。11月23日の論文はそのまま残されています。

もう1つ目につくのは2つの論文の要旨に似た言葉が出てくることです。OpenAI の要旨には「ユークリッド空間で値付けしたテンソルのネットワーク」「回路の計算を配線の予算の中で再現して対角線論法を使う」とあります。Anthropic の論文も、price（値付け）や wire（配線）という言葉を使い、ユークリッド的な場合と対角線論法を使う場合に分けて証明しています。計算機科学者の Scott Aaronson も、ブログで「Anthropic と OpenAI の論文の証明の手法は似て見える」と書いています。

P ≠ NP は解けたのか

解けていません。Anthropic の論文は要旨で「これは P ≠ NP という予想の代数版だが、その予想を解決するものではない」と書いています。

理由は算術回路とふつうのコンピュータの回路（ブール回路）の違いにあります。算術回路は 0 と 1 だけでなく、体のあらゆる値を入れても正しい多項式を計算しなければなりません。ブール回路は 0 と 1 を入れたときに正しい答えを出せば十分です。0 と 1 では \(x^{2} = x\) なので、ブール回路は \(x^{2}-x\) を何倍して足しても答えが変わりません。この自由がある分、ブール回路は算術回路より強いかもしれず、算術回路の下界はそのままではブール回路の下界になりません。

逆向きの関係は知られています。適切な体で VP = VNP なら、ブール回路版の P = NP（P/poly = NP/poly）が従います。しかし VP ≠ VNP から P ≠ NP を導く方法は知られていません。

Fortnow はブログをこう結んでいます。

というわけで、P と NP の問題を決着させるのは、人間にとっても機械にとっても今のところまだはるか先のことだ。

「Lean で検証済み」は何を保証しているのか

ここがこの記事でいちばん伝えたいところです。

リーマン予想の記事では、「証明された」を3つの層に分けて読みました。Lean の記事では、Lean が何を確かめ、何を確かめないのかを詳しく見ました。同じ物差しを、今回の Anthropic の主張に当てはめます。

1つ目の層は強く保証されている

Lean の証明は324ファイル、約7万3千行あります。リポジトリの自動検査では、Lean 本体の kernel に加えて、別の人が独立に書いた2つ目の kernel（nanoda）でも証明を検査しています。使っている公理は Lean の数学で標準の3つ（propext・Classical.choice・Quot.sound）だけです。証明の途中を省略する sorry も、主張を並べた確認用のファイル以外にはありません。

公開の翌日には、第三者による再検査も始まりました。Lean の開発を担う非営利団体 Lean FRO の Kim Morrison は証明を新しい版の Lean に移し、さらに別の2つの kernel（con-leche と con-ron）でも検査が通るようにしています。

「書かれた主張が、書かれた定義のもとで成り立つ」ことについては、人間の査読よりずっと強い保証だと言えます。

2つ目の層はまだ誰も確かめていない

問題は Lean に書かれた主張が本当に Valiant 予想なのかです。主張と定義は Statement.lean という98行のファイルにまとめてあります。README はこの点をはっきり書いています。

証明は Lean が検査するが、このファイルが主張どおりのことを言っているかを確かめる機械はない。

たとえば、算術回路の定義は次のように書かれています。

この定義は短く、教科書の算術回路と同じ形に見えます。しかし、こうした定義がわずかにずれていると、Lean は「別の主張」を正しく検証してしまいます。Lean の記事では、三平方の定理の主張で「平面」を「直線」に書き間違えても、Lean は同じ証明を受理してしまう例を見ました。

確かめる対象は98行なので、量としては専門家が読み切れる範囲です。この層はほかの2つより早く埋まる可能性があります。

3つ目の層は一部しか届いていない

Anthropic の論文は70ページあり、本文の後に証明の全体を載せた付録がついています。ところが付録の前書きは証明の文章の完全さにはばらつきがあると断っています。

専門家はどう見ているか

2026年11月26日時点で、本人の言葉として確かめられた反応を紹介します。

Fortnow は11月24日のブログで、この結果を「今のところ、今年いちばん重要な計算量の結果だ。2026年にそう言うのは大変なことだ」と評しました。証明は代数幾何をほとんど使っていないと指摘し、permanent と行列式の問題に代数幾何で挑んできた幾何学的計算量理論（GCT）にとって何を意味するかは「わからない」としています。同時に、VP ≠ VNP はブール回路の分離を導かないことも説明しています。

Aaronson は11月24日のブログで2つの論文を比べ、Anthropic の下界の方が強いことを紹介しました。証明については「まだ少ししか理解できていない」としつつ、Lean の証明がついていることを重く見ています。そのうえで「証明に本当の技術的な問題があるなら、専門家から喜んで聞きたい」と書いています。

Viola は11月23日のブログで、この結果を歓迎しました。今後は人間が読める部分がさらに短く、大量のコードがついた論文が出てくるだろうとも書いています。

3人とも、自分で証明を確かめたとは書いていません。人間の専門家が証明や Statement.lean を確かめたという報告は、11月26日時点で見つかりませんでした。

何が起きれば「証明された」と言えるのか

今回の主張は、機械による検査が済んだ状態で公開されたという点で、これまでの数学の大きな主張とは違います。足りないのは、次のような人間の側の確認です。

  • 専門家が Statement.lean を読み、Valiant 予想を正しく表していると確かめること（2つ目の層）。
  • 人間が追える形の証明が書かれ、専門家が読んで理解すること（3つ目の層）。
  • そのうえで、論文として査読を経ること。

2つの会社が独立に同じ結論に達したことは、結果が正しいことの傍証にはなりえます。それでも、上の確認の代わりにはなりません。

おわりに

この半年で、AI と数学をめぐる主張は「思いつく」から「Lean の検査を通す」ところまで進みました。8月のゼータ関数の零点も11月20日のリーマン予想も、そして今回の VP ≠ VNP も、Lean の証明とともに公開されています。

Lean は「書かれたことが証明されているか」を、人間よりはるかに確実に確かめます。残っているのは「何を確かめたことになるのか」を確かめる仕事です。それは今のところ、主張を読む人間にしかできません。今回の件はその仕事の重さを、これまでで最もはっきり見せている例だと思います。
