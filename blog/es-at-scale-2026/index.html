2026.11.27解説

強化学習の代わりに「進化」で LLM を鍛える ―― 30個の候補で数十億の重みを動かした論文を読む

LLM を用途に合わせて鍛える「追加学習」では、強化学習が主流になっています。これに対して2025年9月、進化戦略（Evolution Strategies、ES）という古くからある方法で、数十億パラメータの LLM を直接鍛えられたという論文が arXiv に出ました。改訂を経て、2026年7月の機械学習の国際会議 ICML 2026 で発表されています。

驚かされるのは、1回の更新で試す候補がたった30個だということです。ここでいう候補とは、モデルの重みに少しずつ違う揺らぎを足した「モデルの複製」のことです。数十億ある重みをどちらへ動かすかを、30個の複製に問題を解かせた結果だけで決めています。この記事では、進化戦略の仕組み、論文が示した結果、そしてどこまで言えるのかを整理します。

この記事のポイント

  • 進化戦略は、重みに揺らぎを足した候補を試し、点数の良い方向へ重みを動かす方法。勾配を計算せず、推論だけで学習する。
  • 論文は、数十億パラメータの LLM で強化学習より良い結果や安定性を示した。査読（ICML 2026）も通っている。
  • ただし試したのは最大140億パラメータのモデルと限られた課題で、学習全体の計算量では強化学習に劣るという後続の研究もある。

この記事は2026年11月27日時点の情報です。

LLM の追加学習と強化学習

LLM は、大量の文章で事前学習したあとに、特定の課題や好みに合わせて追加で学習させます。これを追加学習（ファインチューニング、事後学習）と呼びます。

いま主流なのは強化学習です。モデルが出した答えに点数（報酬）をつけ、点数が上がるように重みを変えます。PPO や GRPO という手法がよく使われます。ふつうの学習と同じく、どの重みをどちらに動かせばよいか（勾配）を、誤差逆伝播で計算します。

論文は、強化学習の悩みとして次の4つを挙げています。

  • 最後の答えにしか点数がつかない長い課題では、学習が不安定になりやすい。
  • 元のモデルによって、効いたり効かなかったりする。
  • 点数の決め方の抜け穴を突いて、点数だけを上げてしまう（報酬ハッキング）。
  • 同じ設定でも、実行するたびに結果がばらつく。

進化戦略とは何か

進化戦略は、生物の進化になぞらえた最適化の方法です。1回の更新は次のように進みます。

  1. 今の重みに、ランダムな小さな揺らぎを足した候補を N 個作る。
  2. それぞれの候補に課題を解かせて、点数を測る。
  3. 点数の良かった候補の揺らぎの方向へ、今の重みを少しだけ動かす。

式で書くと、更新は次の1行です。

\[ \theta \;\leftarrow\; \theta + \alpha \cdot \frac{1}{N} \sum_{n=1}^{N} R_n \, \varepsilon_n \]

\(\theta\) は今の重み、\(\varepsilon_n\) は n 番目の候補に足した揺らぎ、\(R_n\) はその候補の点数（平均0・標準偏差1にそろえたもの）、\(\alpha\) は動かす幅。点数の高い揺らぎほど強く効く。

ここには勾配が出てきません。必要なのは、候補ごとに課題を解かせて点数を測ること、つまり推論だけです。誤差逆伝播のための計算やメモリが要りません。

コラム：なぜ大きなモデルでは無理だと思われていたのか

進化戦略を深層学習に広めたのは、2017年の OpenAI の論文です。ロボットの歩行やゲームの課題で強化学習と競える結果を出し、1,000以上の計算機に並列で分けられることを示しました。ただ、今回の論文によると、それまでの成功例のモデルは数百万パラメータ以下で、1回に1万個以上の候補を試していました。揺らぎで探す空間は、重みの数だけ次元があります。数十億次元の空間を数十個の候補で探すのは、とても無理だと考えられていました。

論文は何をしたのか

論文は、Cognizant AI Lab を中心とする9人の研究者によるものです。数十億パラメータの LLM のすべての重みに、次元を減らす工夫なしで進化戦略をかけました。

大きなモデルで動かすための工夫は、主に次のとおりです。

  • 揺らぎそのものは保存せず、乱数の種（シード）だけを持つ。同じ種から同じ揺らぎを作り直せる。
  • 揺らぎは層ごとに重みへ足し、評価が終わったら引いて戻す。追加のメモリは1層分で済む。
  • 点数は、候補の間で平均0・標準偏差1にそろえる。
  • 答えの生成では毎回いちばん確率の高いトークンを選び、揺らぎは重みの側だけに入れる。

一方で、進化戦略でよく使われる工夫（点数を順位に直す、最適化手法の Adam を使う、など）はあえて使っていません。単純な形でどこまでできるかを見るためです。設定も全モデルで同じにしました（候補は30個、揺らぎの大きさ0.001、動かす幅0.0005）。比べる強化学習の側は、モデルごとに設定を探して最も良いものを選んでいます。

論文が示した結果

数字を組み合わせる課題で全モデルが強化学習を上回る

Countdown は、与えられた数字を四則演算で組み合わせて、目標の数を作る課題です。最後の答えが合っているかだけで点数がつきます。Qwen2.5 の4つと Llama 3 の3つ、計7つのモデルで比べました。

7つすべてで進化戦略が最も良い結果でした。差が大きいのは Qwen2.5-3B（43.8%に対して60.5%）や Llama-3.1-8B（51.3%に対して61.2%）です。

答えを短くさせる課題で報酬ハッキングが起きない

Qwen2.5-7B に「答えを短くするほど点数が高い」という課題で追加学習させ、どう学ぶかを比べました。強化学習（GRPO）では、元のモデルから離れすぎないようにする罰則を弱くすると、短いが意味のない記号を並べる報酬ハッキングが起きました。進化戦略では、この罰則なしでも起きませんでした。4回の実行のばらつきは、GRPO が進化戦略の15.5倍でした。

数学とパズルでも効果

数学の5つのベンチマークでは、公開されている強い強化学習のモデル3つと「競える」水準でした。論文は、上回ったとは書いていません。パズルでは、ARC-AGI の課題の正答率が Qwen2.5-14B で0.2%から29.5%に、4×4のミニ数独が Qwen2.5-3B で2.5%から69.5%に上がりました。

どこまで言えるのか

ここがこの記事でいちばん伝えたいところです。論文の主張を、言えること、一部しか言えないこと、まだ言えないことに分けます。

計算量の比べ方に注意が要る

論文は、進化戦略は計算量（FLOPs）が少ないと書いています。ただし比べているのは、1サンプルを処理するときの計算量です。

コラム：FLOPs・サンプル・GPU 時間

  • FLOPs：計算機が行う、小数を含む計算の回数。計算の量の目安になる。
  • サンプル：学習に使う問題1つ分。1サンプルを処理するとは、モデルが1つの問題に答え、それに点数をつけて学習に使うこと。
  • GPU 時間：GPU を何台、何時間使ったかの合計。実際の費用に近い物差し。

学習全体の計算量は、おおまかに「1サンプルあたりの計算量 × 使ったサンプルの数」です。1サンプルあたりが少なくても、学習を終えるまでに多くのサンプルが要れば、全体では多くなります。進化戦略は1回の更新で30個の候補それぞれに問題を解かせるので、どちらが少ないかは、1サンプルあたりの量だけでは決まりません。論文は、学習全体の量は比べていません。

学習全体で比べた数字は、後続の研究にあります。2026年8月の CoPES の論文は、Qwen3.5-4B の数学で、GRPO と同じ GPU 時間の予算で比べました。

標準の進化戦略は、GRPO が上げた正答率の伸びの67%分にとどまりました。同じ時間をかけるなら、まだ強化学習のほうが効率が良い場面がある、ということです。

なお、今回の論文の最初の版の要旨は、強化学習より優れる点の1つ目に「サンプル効率」（少ないサンプルで学習できること）を挙げていました。この言葉は、2026年2月の改訂以降の要旨から消えています。

試した範囲は限られている

  • モデルの大きさ：最大でも140億パラメータ（Qwen2.5-14B）。いまの最前線のモデルよりずっと小さい。
  • 課題：Countdown・答えの簡潔さ・数学・2つのパズルだけ。人の好みに合わせる学習のような課題では試していない。
  • 数字の食い違い：数独の正答率が、表では69.5%、付録の本文では66.5%になっている。

なぜ30個で足りるのかはまだわからない

論文は、30個の候補で数十億の重みを動かせた理由を「LLM の本質的な次元が低いことと関係するのかもしれない」としています。

コラム：本質的な次元（内在次元）とは

重みが数十億あっても、課題に合わせて性能を変えるために、本当に動かす必要がある方向はずっと少ないのかもしれない、という考え方です。論文が引用する2020年の研究は、RoBERTa という言語モデルで、ランダムに選んだ200個の方向だけを動かしても、全部の重みを動かしたときの90%の性能が出たと報告しています。大きなモデルほどこの次元が低い傾向がある、とも書いています。動かすべき方向が少なければ、30個の候補でも見当をつけやすくなるはずです。

報酬ハッキングが起きにくい理由についても、論文は仮説を書いています。LLM では、重みを少し変えるだけで点数が細かく上下し、点数の地形がぎざぎざになっています。強化学習の勾配は、このぎざぎざに振り回されやすいといいます。進化戦略は重みに揺らぎを入れて点数を平均するので、地形をならしたうえで登ることになる、という説明です。

どちらの説明についても、直接の証拠はまだだと論文自身が認めています。

後続の研究が続いている

この論文のあと、進化戦略で LLM を学習させる研究が相次ぎました。主なものを並べます。

おわりに

進化戦略は「勾配を使わず、推論だけで学習する」方法です。学習の中身が推論の繰り返しになるので、推論が速く安くなるほど、学習も速く安くなります。トークンの数え方の記事で見た推論の単価や量が、そのまま学習のコストにつながる形です。

進化戦略が強化学習を置き換えるかどうかは、まだわかりません。論文自身も、両者は排他的ではなく、広く探す段階を進化戦略に、細かく詰める段階を強化学習に任せるような組み合わせを提案しています。「大きなモデルには使えない」とされてきた道具が使えるとわかったことで、追加学習の選択肢が1つ増えたのは確かだと思います。
