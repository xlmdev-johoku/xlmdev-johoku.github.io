AI の「使ったトークン数」の数え方

前の記事で取り上げた量子重力の論文には、謝辞に「GPT-6 Astra と何か月もやりとりし、使ったトークンは合計で約4億になる」と書かれていました。

筆者の PC の Claude Code は、直近30日で約29億トークンを使っています。何か月もかけた研究が、筆者の1か月分より少ないのか。そう思って調べてみると、比べ方しだいで「筆者の4日分」にも「18か月分」にもなることがわかりました。この記事では、AI の「使ったトークン数」がどう数えられているのかを整理します。

この記事のポイント

  • トークン数には入力・出力・キャッシュへの書き込み・キャッシュからの読み出し・推論の5種類が混ざる。どれを足すかで数字は何十倍も変わる。
  • Claude Code のようなエージェントは毎回会話全体を送り直すので、量の大半はキャッシュからの読み直しになる。筆者の30日分では約97%だった。
  • 同じ input_tokens という名前でも、Anthropic と OpenAI で中身が逆。数字を比べる前に「何を数えたか」を確かめる必要がある。

この記事は2026年11月27日時点の情報です。料金はすべて定価での換算で、実際の請求額ではありません。

トークンとは何か

トークンは AI が文章を読み書きするときの単位です。単語やその切れ端、日本語なら数文字ほどの塊にあたります。料金も、処理できる量の上限も、トークン数で決まります。

文章をトークンに切り分ける仕組み（トークナイザー）はモデルによって違います。同じ文章でも、モデルが変わればトークン数が変わります。たとえば Anthropic のドキュメントは、Claude Opus 4.7 以降のトークナイザーでは、それ以前のモデルの約1〜1.35倍のトークン数になると書いています。会社が違えば、なおさら1トークンの大きさはそろいません。

1回のやりとりで数えられる5種類のトークン

AI に1回質問して答えが返ってくるまでに、次の5種類のトークンが数えられます。

  • 入力：AI に送る文章。指示や質問、それまでの会話、読ませたファイルなど。
  • キャッシュへの書き込み：入力のうち、次回も使うために AI 側に一時保存した分。
  • キャッシュからの読み出し：前回保存した分を、そのまま使い回した分。同じ文章を最初から処理し直さずに済む。
  • 出力：AI が書いて返す文章やツールの呼び出し。
  • 推論（思考）：答えを出す前に AI が内部で考える分。画面には出ないことが多いが、出力として課金される。

5種類は単価も違います。Claude Opus 5.5 の定価では、100万トークンあたり次のとおりです。

ほかの会社やモデルの単価と、2020年からの値下がりの推移は、コンテンツ「AI サービスのトークン単価」にまとめています。

なぜエージェントでは読み直しが大半になるのか

AI のモデルは、前のやりとりを覚えていません。そのため Claude Code は、1回やりとりするたびに会話全体を送り直します。公式ドキュメントはこう説明しています。

モデルはリクエストの間で何も覚えていないので、Claude Code は文脈全体を送り直す。システムの指示、プロジェクトの文脈、これまでのすべてのメッセージとツールの結果、そして新しいメッセージだ。

Claude Code ドキュメント「Prompt caching」の訳

ツールを1回使うたびにも、その結果を載せて全体をもう一度送ります。会話が長くなるほど、1回あたりに送る量は増えていきます。

架空の例で考えます。1回のやりとりで新しく5,000トークンずつ会話が伸びるとします。20回目には、それまでの9万5,000トークンを読み直してから、新しい5,000トークンを足すことになります。

20回の合計では、新しく足したのは10万トークン、読み直したのは95万トークンです。会話が長くなるほど、読み直しの割合は大きくなります。

筆者の PC の Claude Code の直近30日分（2026年11月27日時点の /stats の表示）を見ると、実際にそうなっていました。

29億のうち、新しく処理した分（書き込み・出力・入力）は約1億で、全体の3%ほどしかありません。「入力」がほぼ0なのは、送ったものがほとんどキャッシュの書き込みか読み出しとして数えられているからです。

コラム：同じ画面に2つの数え方

Claude Code の /stats の画面には「Total tokens: 2.9b」の下に、「入力と出力は『ホビット』のトークン数の約178倍」という一文も出ます。こちらは入力と出力だけ（約2,200万）で比べた数字で、キャッシュの分を含みません。作業中にスピナーの横に出るトークン数も、そのターンの出力だけを数えています。同じ道具の中でも、場面によって数え方が違うわけです。

同じ input_tokens でも中身が逆

API の応答には、使ったトークン数が usage という欄で返ってきます。ここでも会社によって数え方が違います。とくに紛らわしいのが input_tokens です。

  • Anthropic：input_tokens は、キャッシュに当たらなかった残りだけです。送った入力の全体は、input_tokens・cache_creation_input_tokens・cache_read_input_tokens の3つを足して求めます。
  • OpenAI：input_tokens に、キャッシュから読んだ分も書き込んだ分も含まれます。ふつうの入力は、そこからキャッシュの分を引いて求めます。

OpenAI のドキュメントにある例の数字を使って、同じ中身のリクエストを両社の形式で書くと次のようになります。

「input_tokens の合計」を両社で比べると、片方はキャッシュの分を含み、もう片方は含みません。同じ名前の欄を足し合わせただけでは、比べたことになりません。

推論の扱いにも注意が要ります。OpenAI の例では、出力1,186トークンのうち1,024トークンが画面に出ない推論です。推論を多く使うモデルでは、出力のトークン数の大半が、読者の目に触れない部分になります。

トークンの量と料金は別

キャッシュからの読み出しは単価が安いので、量の割合と料金の割合は一致しません。筆者の30日分を、すべて Claude Opus 5.5 の定価で換算してみます。

量では97%近い読み出しが、料金では4割ほどにとどまります。2,200万トークンしかない出力が、料金では3割前後を占めます。「何トークン使ったか」と「いくらかかったか」は、別の問いです。

なお Claude Code は、サブスクリプションの範囲内では本体の会話に1時間保存のキャッシュを使い、サブエージェントなどには5分保存を使います。筆者の書き込みのうち、どれだけがどちらだったかはわからないので、表では幅をもたせました。

発表されたトークン数をどう読むか

AI を使った成果の発表では、使ったトークン数が書かれることが増えました。その数え方はそろっていません。

  • Anthropic は2026年8月、Claude がゼータ関数の零点の研究で成果を出した件について「出力3,100万トークン」と、出力だけを公表しました（リーマン予想の記事）。
  • 量子重力の論文は「約4億トークン（total tokens spent）」と書いていますが、何を足したのかは書いていません。

論文の4億を、筆者の30日分と比べるとこうなります。

トークン数を見たら、少なくとも次の4つを確かめると、比べられるかどうかがわかります。

  1. キャッシュからの読み出しを含むか。
  2. 推論（思考）のトークンを含むか。
  3. どのモデルか。トークナイザーが違えば、同じ文章でも数が変わる。
  4. サブエージェントや並行したセッションを含むか。期間はどれだけか。

おわりに

4億という数字を見たとき、筆者はまず「少ないトークンで重大な科学的発見ができるのなら、それは素晴らしいことだ」と思いました。今もその気持ちは変わりません。ただ、調べてみると、トークン数は数え方しだいで何十倍も変わる数字でした。

トークン数は計算機をどれだけ使ったかの目安です。研究の手間や発見の価値をそのまま表す物差しではありません。人間が考えた時間は、どの欄にも出てきません。AI を使った成果を発表するときは、トークン数と一緒に「何を数えたか」も書いてもらえると、読む側は比べることができます。
